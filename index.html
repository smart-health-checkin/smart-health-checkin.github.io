Open protocol · draft 1.0

Pre-visit check-in over the Digital Credentials API

A provider's page asks the patient's health app for what the visit needs, and the verified answer comes back to that same page.

Check in from a phone

The patient is on their phone. They tap, choose their health app, approve the items, and the page renders the response in place. Needs a wallet on the phone; on a desktop the browser offers a QR code instead.

Check in at a kiosk

A screen with no wallet of its own shows a QR code. The patient's phone asks its wallet, and the sealed answer comes back to the screen — only the screen can open it.

Try it → Any browser

Check in with a web wallet

No phone needed. A demo wallet opens in a tab with a real consent screen, and the page gets the same sealed response over the same wire.

The wire

Protocol id
org-iso-mdoc, direct — no OpenID4VP layer
docType
org.smarthealthit.checkin.1
Payload
The whole response JSON in one mdoc element
Encryption
HPKE, to a key your page mints per request
Signatures
COSE_Sign1 over the MSO, plus a device signature
Origin binding
In the session transcript — a response captured elsewhere will not open

Where this stands

  • Works Verified byte for byte against real Chrome-on-Android captures. Desktop gets a QR code the phone answers.
  • Draft An editor's draft. Identifiers, wire format and clinical model are stable; wording is still moving.
  • Missing Real patient wallets. There is a reference web wallet, an Android wallet, and a mock for tests.
